## 1단계 — 숫자 신뢰도 (틀린 값부터 고친다)

화면 맨 위 "평균 괴리율"이 +57%로 나온다. 원인이 되는 데이터 오류가 실측으로 확인됐다.

| # | 문제 | 실측 | 조치 |
|---|---|---|---|
| 1-1 | 한경 소스에서 종목이 증권사 자신으로 매핑됨 | 4건. 예: 종목 "한화투자증권"·목표가 98,000·현재가 3,690 → 괴리율 +2,555% | 한경 파서의 종목 추출 수정, 종목명=증권사명이면 폐기 |
| 1-2 | 목표가 파싱 오류 | NH 롯데웰푸드 5,000(현재가 126,900), 한투 파마리서치 23,068·HL만도 3,898, KB LG이노텍 2,000,000(현재가 291,500, 원문 미확인) | 목표가가 현재가의 0.3~3배를 벗어나면 격리하고 화면에 "확인 필요" 표시. 한투 본문 추출 규칙 보강 |
| 1-3 | 같은 종목·날짜·증권사 중복 | 163그룹 (한경+네이버 95, KB끼리 47, 네이버끼리 11) | 병합 키 (code, date, 증권사)를 실제로 강제. 빈 필드는 서로 채움 |
| 1-4 | 목표가는 있는데 의견이 NR | 121건 (KB 56, 한투 33, NH 18, 네이버 13) | 같은 종목+증권사 직전 의견 승계, 화면에는 "유지 추정" 구분 |
| 1-5 | 평균이 이상치에 끌려감 | 평균 +81.0%, 중앙값 +64.8%, +100% 초과 1,210건 / 4,557건 | 요약 수치를 중앙값으로 교체. 발간 시점 괴리율(`price_at_write`)과 현재 괴리율을 구분 표시 |

중앙값 +64.8%도 통상 수준보다 높다. 1-1~1-3 수정 후 다시 측정해 남는 원인을 확인한다.

## 2단계 — 속도

| # | 문제 | 조치 | 기대 효과 |
|---|---|---|---|
| 2-1 | 기간 필터와 무관하게 5,439건 전체 로드 | 최근 30일 파일 + 월별 아카이브로 분할, 아카이브는 "전체" 선택 시 로드 | 초기 로드 건수 약 41% (2,255 / 5,439) |
| 2-2 | 요약문이 파일의 절반 | 요약(4.0MB / 7.4MB)을 별도 파일로 분리, 행을 펼칠 때 로드 | 목록 파일 약 절반 |
| 2-3 | `cache:"no-store"`로 매번 재다운로드 | `meta.json`의 `updated_at`을 버전 쿼리로 붙여 브라우저 캐시 사용 | 재방문 시 다운로드 0 |
| 2-4 | 5분마다 `updated_at`이 바뀌면 전체 재다운로드 | 당일 파일만 다시 받음 | 장중 트래픽 감소 |
| 2-5 | 폰트 1.25MB가 HTML에 내장 | 별도 파일로 분리해 캐시 (우리다움체 내장 방침은 유지) | HTML 1.66MB → 약 0.4MB |
| 2-6 | 안 보이는 탭도 미리 그림 | 탭을 처음 열 때 렌더 | DOM 노드 감소 |
| 2-7 | 매 실행 7.7MB 파일 전체를 커밋 | 2-1 분할 후에는 당월 파일만 변경됨 | 저장소 증가 속도 완화 |
